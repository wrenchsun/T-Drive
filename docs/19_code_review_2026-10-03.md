# 19. コードレビュー結果（FacialController、2026-10-03）

- 対象: v0.4.0（`a9ead57`）以降〜 `5d65bd3` の FacialController 一式（Maya: `tdrive` / `tdrive_facial`、Unity: `com.tdrive.facial`）
- 方法: opus のレビュー担当 5 人が領域ごとにコードを読んだ結果（読み取りのみ。Maya・Unity は起動していない）。**「確認済み」= コードを読んで確かめたもの。実機での再現はしていない**
- 総評: 計算のコア（重み・スムージング・自動生成・座標変換）は UE 版に忠実で、数式の誤りは見つからなかった（座標変換は数値実験でも確認）。問題は **Maya / Unity との境目**（保存・Undo・リロード・状態の後始末）と **実モデルでの前提**（単位・スケール・バインドポーズ）に集中している
- 状態の列: ⬜ 未対応 / ✅ 修正済み（コミット）/ — 対応しない（理由）
- 修正の決まり: 指摘の場面を再現するテストを先に書き（失敗する）、直して通す。実機でしか確かめられないものは [18](18_manual_verification_facial.md) に確認項目を足す

## 6. テストの穴

- テスト用の合成モデルが「cm・スケールなし・参照なし・アニメなし・blendShape が 1 つ」で、実モデル特有の問題（S-1〜S-3、S-6）を検出できない → 単位 m・親スケール・アニメ付きの変種を足す
- 編集中の保存 → 開き直し、未保存のままリロード、殻の開く / 閉じる / 古い枠からの復元、Maya の Undo との関係、のテストが無い
- UI の約束の静的テスト（`test_ui_patterns.py`）が、scriptJob の一般的な書き方・`userSetup.py`・2 引数のシグナルを見逃す
- Unity: 「割り当て 0」のテストが Unity の環境で常に 0 を返して何も証明していない可能性（わざと割り当てて失敗するか確かめる）/ 「プレビューがシーンを汚さない」テストがシーンに無いオブジェクトで行われている / 再生中のカットシーン・実際のアセットの取り込み・保存が自動テストに無い / 一部のテストが開いているシーンにオブジェクトを作る
- 共通のテストデータのうち自動生成・画面の状態は Python 版自身が作った期待値（回帰の検出のみ）
