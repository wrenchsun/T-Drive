- 作成: 2026-10-03
- 移植元: `C:\Users\yamag\wrench\ue\FacialController_UE`（UE 5.8 プラグイン。以下「UE 版」。設計の出典は同リポジトリの `Docs/FacialController_アーキテクチャ設計_v2.md` = 「v2」、`Docs/Porting/00・01・03`）
- 関連: 設計 = [15](15_facial_controller_design.md)、D-Drive 側の変更調査 = [16](16_ddrive_changes_for_facial.md)、チケット = [tasks.md](tasks.md) Phase S / F

## 1. これは何か

アニメ調の顔は、あおり・ふかん・横顔で形が崩れる。FacialController は **カメラから見た顔の角度（Yaw × Pitch の格子）ごとに補正ポーズを作っておき、
実行時にカメラの角度で補間して顔の形を補正する** 仕組み（参考: 東映 Dynamic Japanimation のカメラアングル補正、orange の Camera-O-Matic）。

```
作る（Maya）: 格子の点（例: 正面・右 45°・右 90° × ふかん・水平・あおり）ごとに補正ポーズ（シェイプの重み + ボーンのずらし）を作る
              → 足りない点は自動で埋める（左右ミラー + 補間）→ 点ごとに 1 個のブレンドシェイプ FC_* に焼く
使う（Unity）: カメラと頭の向きから Yaw / Pitch を求め、まわりの 4 点の FC_* を重み付きで足す（感情レイヤーは上乗せ）
```

汎用の表情コントローラー（表情プリセットの切り替え・まばたき・視線）ではない。リップシンクは UE 版でも未実装で、本仕様では対応表だけを扱う（§8 R-18）。

### 1.1 既存機能との関係

| 既存 | 関係 |
|---|---|
| カメラ角度補正 BlendShape（T-20、[05](05_maya_tool_spec.md) §3.2、`characterSettings.viewCorrection`） | 正面・3/4・横の 3 キーだけの簡易版。FacialController はその上位版（格子・ふかん/あおり・感情レイヤー・自動生成）。**T-20 は残す**（削除は MAJOR）。T-20 のデータを FacialController の格子へ取り込む移行機能を用意し（F1-9）、新しく作るキャラクターは FacialController を使う |
| ルック（Toon シェーダー） | 独立して使える。連携は任意: FacialController が出す角度・感情の値をマテリアルへ渡し、角度に応じた線幅・顔影などに使える（§6.4、R-14） |
| アニメーション系（Phase A、T-31〜T-39） | 別物。Phase A の「カメラ依存のポーズ補正（T-38）」は体のポーズ、FacialController は顔の形 |

## 2. 役割分担

| 環境 | 役割 | 内容 |
|---|---|---|
| **Maya** | **データの作成・編集** | 格子・ポーズ・感情レイヤーの編集、自動生成、シェイプ作成の効率化（§5.6）、ベイク、検証・リペア、カメラ連動プレビュー、Unity 向け出力（FBX + JSON） |
| **Unity** | **ランタイム・プレビュー・簡単なパラメータ調整** | 補正の実行（カメラ → 重み → ブレンドシェイプ）、エディタでのプレビュー・格子の閲覧・検証、強さ・追従の速さなどの調整（§6.3）、Timeline での演出 |

- Unity ではポーズの編集・ベイクをしない（UE 版移植計画の「Unity 段階 2」は対象外。必要になったら別途）
- **ソースが正、ベイク結果は作り直せるもの**: 交換するのはソースデータ（`.fcpose.json`）と、FC_* シェイプ入りの FBX。Unity が使う FBX は必ず Maya でベイクしたもの（頂点の並びが一致するため）

## 3. 互換性の条件

| 相手 | 条件 |
|---|---|
| **UE 版** | 交換形式 `.fcpose.json`（`"format": "FacialCorrection"`, `version` 1）を**そのまま読み書きできる**。T-Drive が足す項目は追加キーだけ（UE 版は未知キーを無視する）。重みの計算は UE 版 `FacialCore` と同じ結果（共通のテストデータで確認、§9） |
| **T-Drive** | 同じ Maya モジュール・同じプロジェクトフォルダ・同じリリース（VERSION・タグ）。エディタは「T-Drive › Toon / FacialController」の 2 段タブ（§5.1）。Toon を使わないキャラクターにも単独で使える |
| **D-Drive** | D-Drive を変更しなくても動く: Unity パッケージは D-Drive に依存せず、D-Drive のモデル Prefab にコンポーネントを付ければ動く。D-Drive の TimeLine（Cutscene = Unity Timeline の薄いラッパー）上で、FacialController のトラックがそのまま再生・シーク・同期される。D-Drive 側を変えるとより良くなる点は [16](16_ddrive_changes_for_facial.md) |
| 個別サポート | 一部の機能は環境ごとに対応が違ってよい（§8 の表に明記）。例: 重みのスムージングは Unity だけ、カメラ連動のキー焼きは Maya だけ |

## 4. データ

### 4.1 置き場所

```
<プロジェクトフォルダ>/
├─ looks/<character>/look.json                 （既存。Toon）
└─ facial/<character>/
    ├─ <character>.fcpose.json                  ★ FacialController のソース（唯一の真実）
    ├─ profiles/<name>.fcprofile.json           命名規則プロファイル（任意。標準シェイプ名・左右の接尾辞・可動域）
    ├─ poses/<name>.fcpose.json                 1 点分のポーズ（"format": "FacialPose"。ポーズの持ち運び・カット補正用）
    └─ export/unity/                            Unity 向け出力（FBX・JSON の写し）
```

- Maya シーンには「どの `.fcpose.json` を開いていたか」だけを記録する（Look と同じ fileInfo 方式）。シーン保存でソースも保存する
- ベイク結果（FC_* シェイプ）は Maya シーンと FBX の中にあり、いつでも作り直せる

### 4.2 `.fcpose.json`（UE 版と同じ形式 + 追加キー）

UE 版が書き出す形（v2 §3.5、実装は UE 版 `FacialPoseJson.cpp`）:

```jsonc
{
  "format": "FacialCorrection", "version": 1,
  "meta": { "unit": "cm", "upAxis": "Y", "handedness": "right", "source": "Maya2026 T-Drive 0.5.0" },
  "grid": { "yawRange": 90, "pitchRange": 45, "cols": 5, "rows": 3,
            "baseBone": "bone_head", "forwardAxis": "+Z", "centerOffset": [0, 0, 0], "edgeFade": 15 },
  "policy": { "expressionDampen": 0.5, "interpSpeed": 10, "snapAngle": 45, "fade": [0, 0], "globalAlpha": 1 },
  "layers": [
    { "name": "Neutral", "emotionCurve": "", "enabled": true,
      "points": [ { "row": 1, "col": 4, "isKey": true,
                    "curves": { "bs.mouth_left": 0.4 },
                    "bones":  { "bone_eye_L": { "t": [0, 0, 0], "r": [0, 0, 0, 1], "s": [1, 1, 1] } } } ] }
  ],
  "workingSet": { "curves": [], "bones": [] },
  "mirror":  { "enabled": true, "suffixL": "_L", "suffixR": "_R", "exclude": [], "boneAxis": "X" },
  "autogen": { "mode": "IDW", "idwPower": 2.0 },
  "exclude": { "curves": [], "bones": [] },
  "intensityCurves": [],
  "profile": "shizuku"
}
```

意味（UE 版と同じ。変えない）:

- 格子の点は行優先（`index = row * cols + col`）。点の角度 = `((col / (cols−1)) * 2 − 1) * yawRange`、行も同様に `pitchRange`。行 0 が −Pitch（あおり = カメラが下）、中央が正面
- レイヤー 0 は必ず `Neutral`（補正の基本）。それ以外は感情レイヤー（最大 15）で、**Neutral との差分**として焼き、感情の重みを掛けて上乗せする
- `curves` = シェイプ名 → 重み（0〜1。誇張は 2 まで、§8 R-37）。`bones` = ボーン名 → 親ボーン空間での加算（適用順 Scale → Rotation → Translation、クォータニオンは `[x, y, z, w]`）
- 書くのは作った点（キー・自動生成）だけ。名前の照合は**大文字小文字を区別する完全一致**
- 座標系は `meta` に書いた系で保存する（Maya = cm / Y-up / 右手）。読む側が自分の系と違えばボーンのずらし・`centerOffset`・`forwardAxis`・`boneAxis` を変換する。シェイプの重みは変換不要
- `forwardAxis`: UE 版は `+X / -X / +Y / -Y`。Y-up の環境のために **`+Z / -Z` を追加**（追加キーではなく値の追加。UE 版へ持ち込むときは変換して `±X/±Y` に直す）

**T-Drive が足すキー**（すべて省略可。UE 版は無視する。UE 版が同じ機能を実装するときはこの名前に合わせる）:

```jsonc
{
  "asset": "shizuku",                                   // FC_<asset>_<layer>_R{r}_C{c} の <asset>。UE 版の JSON には入っていない（アセット名から決まる）ので補う
  "target": { "mesh": "mdl_face02", "extraMeshes": [] }, // 焼く先のメッシュ（まつ毛など別メッシュも同じ重みで動かすとき extraMeshes）
  "bake": { "deltaThreshold": 0.001, "differential": true },
  "limits": { "bs.mouth_smile_L": [0, 1] },             // 可動域（R-16）。プロファイルの値をキャラクター単位で上書き
  "material": { "mode": "none" },                        // "none" | "propertyBlock"（R-14、§6.4）
  "quality": { "sharpness": 1.0, "stepFps": 0, "angleEpsilon": 0.1, "maxLod": 0 },   // R-32 / R-33 / 軽量化
  "perspective": { "enabled": false, "axis": "distance", "strength": 1.0, "keys": [ { "value": 30.0, "curves": {}, "bones": {} } ] },  // R-34 パース補正（§5.8b）
  "layerWeights": { "<layer>": { "source": "curve" } },  // R-35 重みの入力元（"curve" | "direct" | "distance"）
  "sculptShapes": { "prefix": "fcs_" }                   // §5.6 「この角度で彫る」で作る補助シェイプの接頭辞
}
```

### 4.3 ベイクで作るもの

| もの | 名前 | 中身 |
|---|---|---|
| 角度の補正シェイプ | `FC_<asset>_<layer>_R{row}_C{col}` | その点のポーズを当てた形 − 何も当てない形（感情レイヤーはさらに Neutral との差分）。`bake.deltaThreshold`（cm）未満の頂点は捨てる |
| 誇張用（R-37） | `FC_<asset>_<layer>_R{row}_C{col}_Ex` | 重みが 1 を超える分 |
| パース補正（R-34） | `FC_<asset>_Persp_K{n}` | 画角 / 距離のキーごと |

> **誇張と除外の決定（2026-10-03）**
> - 誇張の強さ（0〜1）は `.fctrack` に入れる（固定カーブ `exaggeration` を追加。無いファイルはデータの既定値のまま = 追加のみ）。Maya のプレビューの「誇張」に打ったキーが Timeline に渡る
> - Maya のシーンでの 1 超は **元シェイプの直線の延長**のまま。シェイプタブの誇張形（`<名前>_Ex`）へのクロスフェードはしない。ベイクはシーンで見えている形を焼くので、見た目と `FC_…_Ex` は一致する
> - 除外パターンを変えたら自動で「変更あり」: ベイク時の除外パターンを記録し、今と違えば全点を焼き直しの対象にする（ポーズごとの印は変えないので、既存データが一斉に変更ありにはならない）

- **`FC_` で始まるシェイプだけ**を作り直す・消す。モデルに元からあるシェイプ（`bs.*`）には触らない（CLAUDE.md「元を破壊しない」）
- **Unity でのシェイプ名**: FBX を Unity に取り込むと、シェイプ名は `<blendShape ノード名>.<ターゲット名>` になる（shizuku の実物で確認: `bs.FC_shizuku_Neutral_R0_C0`）。Unity 側は「完全一致 → `.` + 名前で終わるもの」の順で探す（ランタイム・検証・格子ビューア共通）
- 焼いた点と名前の対応は `.fcpose.json` には書かない（名前は規則から決まる。Unity は名前でシェイプを探し、無ければその点を飛ばす = フェイルソフト）

### 4.4 命名規則プロファイル（`.fcprofile.json`、R-15）

```jsonc
{ "format": "FacialNamingProfile", "version": 1, "name": "shizuku", "description": "bs.* 命名（kuromaru9 shizuku）",
  "standardCurves": ["bs.eye_close_L", "bs.eye_close_R", "..."],   // あるべきシェイプの一覧（不足チェック用）
  "mirror": { "suffixL": "_L", "suffixR": "_R", "exclude": [] },
  "limits": { "bs.jaw_open": [0, 1] } }
```

プリセット: ARKit 52（Left/Right）、VRChat ビセム（`vrc.v_*`）、MetaHuman（名前一覧なし）、shizuku（`bs.*`）。プロファイルを選ぶと、ミラーの規則・可動域が自動で `.fcpose.json` に入る（UE 版では手で写す必要があった = 未実装項目）。

- プリセットはツールに同梱（`maya/scripts/tdrive_facial/profiles/`。`name` = ファイル名）。プロジェクトの `facial/<character>/profiles/` に同じ名前があればそちらを優先
- プロファイルを選んだとき: ミラーの接尾辞・除外は置き換える。可動域は足し合わせ、キャラクター側（`limits`）に既にある値を優先
- ミラーの除外パターンは部分一致。プリセットは標準シェイプの可動域をすべて 0〜1 にしている。可動域の指定が無いシェイプも 0〜1 として扱う（1 を超える誇張は `limits` で上限を上げたものだけ）
- shizuku のシェイプ名はモデルの綴りのまま（`bs.eye_libUp_L` と `bs.eye_lidUp_R` は左右で綴りが違うので、検証に「ミラーの相手が無い」と出る。モデル側の名前なのでそのまま）

## 5. Maya（作成・編集）

### 5.1 画面構成（2 段タブ）

```
┌ T-Drive 0.5.0 ─────────────────────────────────────────────────────┐
│ [ Toon ] [ FacialController ]                    ← 1 段目（ツール）  │
├────────────────────────────────────────────────────────────────────┤
│（Toon）       Look: … [新規][開く][保存]  表示: Toon / 元の見た目    │
│               部位 | ルック | キャラクター | 機能 | A/B | プレビュー │
│（Facial）     データ: facial/shizuku/shizuku.fcpose.json ●未保存     │
│               [新規][開く][保存]  プレビュー: (●補正あり ○なし)      │
│               セットアップ | グリッド | ポーズ | シェイプ | レイヤー | 検証 | 出力 │
└────────────────────────────────────────────────────────────────────┘
```

- メインメニューは「T-Drive Toon」→ **「T-Drive」** に変える（エディタ・プロジェクト・マニュアル・更新は共通。Toon 表示 ON/OFF などは Toon のサブメニュー）
- ウィンドウ名・ドッキングの見出しは「T-Drive <版>」。前回のドッキング位置は引き継ぐ（古い枠は自動で片付ける）
- 2 つのツールは別々のファイル（Look / fcpose）を開く。未保存の印・Undo（Ctrl+Z）は開いているツールのもの

### 5.2 セットアップタブ

- 対象: 顔メッシュ（複数可）、基準ボーン（頭。**自動検出**: 有名な命名 → 部分一致）、顔の前方向の軸、中心のずらし
- 格子: Yaw / Pitch の範囲、列・行の数、端のフェード角度。**格子の大きさを変えても作った点は角度で引き継ぐ**（UE 版は番号で引き継ぐので角度がずれる。T-Drive は意図的に変えている）: 新しい格子の点と同じ角度（1e-3° 以内）の元のキーはキーのまま、ほかの点は元のキーから補間し直す。新しい格子に乗らなくなったキーは一覧で知らせる
- 命名規則プロファイルの選択・編集・保存（§4.4）
- 作業セット: このキャラクターの補正で触るシェイプ・ボーンを選ぶ（ポーズタブはこれだけを表示）。選ぶとビューポートで影響する頂点 / ボーンを強調表示
- T-20 のデータを取り込む（正面・3/4・横 → Yaw 0° / 45° / 90°、Pitch 0° のキー）

### 5.3 グリッドタブ

- 格子の図: 緑 = キー、水色 = 自動生成、灰 = 空、枠 = 未ベイク / ベイク後に変更あり。**今のカメラの角度を赤い点で表示**（カメラを動かすと追従）
- 点をクリック → その角度へカメラを移動（基準ボーンを注視）+ その点のポーズをシーンに当てる。未保存の編集があれば確認
- ボタン: 自動生成 / キー解除 / クリア / 他のデータからコピー（全レイヤー・作業セットだけ・キーだけ）/ ベイク（全部・この点だけ）
- 右クリック: キー解除、クリア、この点だけベイク、ポーズのコピー / 貼り付け / 左右反転して貼り付け、カメラをこの点へ
- 集計: キー / 自動生成 / 空 / 未ベイクの数
- 任意: 点ごとのサムネイル（その角度から見た顔の小さな画像）、ビューポートに格子の球を表示して点をクリック

**自動生成**（UE 版と同じ規則）: キーを集める → ミラーがオンなら −Yaw 側に仮想キーを足す（鏡映した角度から 1° 未満に他のキーがあれば足さない。自分自身も数えるので、Yaw がほぼ 0° のキーは鏡映されない。左右の接尾辞を入れ替え、ボーンのずらしを鏡映。除外パターンはシェイプにもボーンにも効く）→ 残りの点を IDW（距離は範囲で正規化、重み `1/d^power`）または最近傍（度のまま、正規化なし）で埋める。1e-3 以下の重みは捨てる。ボーンのスケールは補間しない（常に 1。鏡映したボーンもスケール 1）。キーの点は変えない。自動生成した点は未ベイクになる。

### 5.4 ポーズタブ

- **シェイプ**: 作業セットのスライダー（絞り込み付き、範囲は可動域）。Maya の Shape Editor・チャンネルボックスで動かした値もそのまま取り込む
- **ボーン**: **Maya の移動 / 回転ツールをそのまま使う**（専用ギズモは作らない）。編集中に動かしたジョイントの、基準からのずれを取り込む。一覧に数値も出す
- ボタン: 保存（この点をキーにする）/ 読み直す / ゼロに戻す / ボーンを戻す / 左右反転 / この点を書き出し（`poses/*.fcpose.json`）/ 読み込み
- **アニメから読み込む**: 今のフレームの値、または Unity の `.anim`（ブレンドシェイプのカーブ）からポーズを取り込む（作業セットだけ、の指定可）
- プレビュー: 補正あり / なし、A/B（補正前後を交互）、ターンテーブル、感情の重みスライダー、土台の表情を当てた状態で確認
- **土台の表情**（2026-10-03 決定）: 表情（Unity の .anim など）をシーンにだけ下敷きとして当てる。同じシェイプは **土台 + ポーズ**（ゲームと同じ足し合わせ。丸めない）。スライダーはポーズの値のまま、横に「+0.60（土台）」と出す。可動域を超えたら警告色。「シーンから取り込む」は土台ぶんを引く。データ・ベイク・出力には入らない。編集状態の間だけ有効（編集を終える・ベイクすると外れる）。ボーンは対象外

### 5.5 レイヤータブ（感情）

- Neutral + 感情レイヤー（プリセット: Anger / Contempt / Disgust / Fear / Joy / Sadness / Surprise、自由な名前も可）。追加・改名・有効 / 無効・削除（削除するとその FC_* も消す）・他のレイヤーからポーズをコピー
- 感情の重みの入力元の名前（`emotionCurve`。Unity ではコンポーネントの値 / Timeline / Animator のパラメータから入る）
- 表情が強いときに補正を弱める設定（`expressionDampen` と、強さを測るシェイプの一覧）

### 5.6 シェイプタブ（Maya ならではの作成支援）

リグは作らず（リギングツールは対象外、§10）、Maya 標準の blendShape・スカルプトの上に載る道具だけを用意する。

| 機能 | 内容 |
|---|---|
| **この角度で彫る** | 格子の点を選んで押すと、その角度のカメラのまま、スカルプト用のシェイプ `fcs_<layer>_R{r}_C{c}` を作って編集状態にする。彫った結果は**モデルのシェイプ**として残り、その点のポーズには「`fcs_…` = 1」と記録される（ソースは名前と重みだけ、という形式を崩さずに頂点単位の修正ができる）。ベイク後は FC_* に含まれるので、`fcs_*` は Unity へ出さない |
| **ポーズをシェイプにする** | 今のスライダー + ボーンの状態を 1 個のシェイプとして取り出す（よく使う組み合わせを 1 本のスライダーに） |
| **左右に分ける** | 左右一体のシェイプを `_L` / `_R` に分ける（中央のぼかし幅を指定）。分けた結果をすぐ確認 |
| **ミラー** | `_L` から `_R` を作る / 更新する（トポロジ対称・位置対称。対称でない頂点を一覧表示） |
| **中間・誇張** | 既存シェイプに中間形（in-between）や 1 を超える誇張形（R-37）を足す |
| **組み合わせ補正** | 2 つのシェイプを同時に上げたときの破綻を直す補正シェイプ（combination shape）を作る |
| **別メッシュへ写す** | 顔のシェイプを、まつ毛・眉・別衣装の頭など別メッシュへ写す（頂点が同じなら複写、違えば近接で転写） |
| **整理** | 動いていない頂点の微小な差分を掃除、空のシェイプ・未使用のシェイプの一覧、プロファイルに沿った一括改名、不足している標準シェイプの一覧 |
| **比べる** | 補正前後・左右・他の点とのゴースト表示 |

### 5.7 ベイク

1. 基準の姿勢（バインドポーズ、土台の表情なし）にする
2. 点ごとに: ポーズを当てる（シェイプの重み + ジョイントへずらしを加算）→ 変形後の頂点を読む → 何も当てない頂点との差分
3. 感情レイヤーは Neutral との差分にする。しきい値未満を捨てる
4. 顔メッシュの blendShape にターゲット `FC_*` を追加 / 置き換え（`target.extraMeshes` も同様）
5. 結果の要約（作った数・頂点数・捨てた量・所要時間）を表示。孤立した `FC_*`（格子に対応がないもの）は掃除

- 法線は焼かない（Maya と FBX が再計算する。Unity 側の取り込み設定は §6.1）
- ベイクは Maya の Undo 1 回で戻せる

### 5.8 カメラ連動プレビュー（Maya のランタイム相当）

- 選んだカメラ（既定 = 今のビューのカメラ）と基準ボーンから Yaw / Pitch を求め、FC_* の重みを動かす。**カメラを回す・再生する・レンダリングする、のどれでも追従**
- プラグインを使わない（標準ノードと expression で組む。シーンを他の人が開いても壊れない）。式は §9 の共通の計算と一致することをテストで確かめる
- 手動の角度指定、感情の重み、全体の強さ（いずれもキーが打てるアトリビュート）
- **キーに焼く**（R-19）: 今のカメラで時間範囲をサンプルして FC_* の重みにキーを打つ（仕組みを外して他へ持ち出せる）
- スムージング・スナップ・距離フェードは Maya では掛けない（Unity の品質機能）

### 5.8b パース補正（R-34、F5-4。2026-10-04 決定）

広角で寄ったとき（鼻が大きく、耳が小さく見える）だけ、奥行きを押さえる補正を足す。角度の格子とは別の、**1 本の軸に並んだキー**で持つ。

- **軸**（`perspective.axis`）: `distance`（カメラと格子の中心の距離。データの単位 = cm。既定）か `fov`（カメラの縦の画角。度）。パースの強さを実際に決めるのは距離なので、既定は距離。画角は「広角レンズのときだけ」と指定したい場合に使う
- **キー**（`perspective.keys`）: `{ "value": 数, "curves": {シェイプ名: 重み}, "bones": {ボーン名: オフセット} }` の配列。`value` は軸の値。同じ `value` は不可。**配列の順番がシェイプの番号**（`FC_<asset>_Persp_K{n}` の n。並べ替えても番号は変えない = 名前が安定する）。最大 8 個
- **重み**: キーを `value` の昇順に並べ、今の軸の値を挟む 2 つのキーの間を直線で混ぜる（重みの合計 = 1）。いちばん小さいキーより下・いちばん大きいキーより上では、端のキーが 1 のまま。「補正なし」の範囲は、**空のポーズのキー**を置いて作る（例: 30 cm = 補正あり、80 cm = 空 → 80 cm より遠くは補正なし）。キーが 1 個なら常に 1
- **合成**: 角度の補正（全レイヤーの合計）に**足す**。全体の強さ（alpha・距離フェード・表情での弱め）は同じように掛かる。感情レイヤーの重み・シャープさ・誇張は掛からない。パース補正の強さ（`perspective.strength`、0〜1、既定 1）を別に持ち、Unity の調整値と Timeline のクリップで変えられる
- **ベイク**: キーごとに、基準姿勢からの差分を `FC_<asset>_Persp_K{n}` に焼く（Neutral との差分にはしない。足し合わせなので）。空のキーはシェイプを作らない。重み 1 超は丸める（誇張用の分割はしない）
- **視点に画角が無いとき**（Unity で視点が Transform だけ、など）: 軸が `fov` ならパース補正は 0。軸が `distance` なら距離だけで決まる
- `perspective.enabled` = false、またはキーが無いときは何もしない（今までと同じ結果）

Maya の画面（グリッドタブの下の「パース補正」の箱）:

- 「使う」のチェック、軸の選択、キーの一覧（値・ポーズの有無・ベイクの状態）、「キーを足す」「値を変える」「削除」
- キーを選ぶと、**そのキーが編集の対象**になる（ポーズタブのスライダーは、格子の点の代わりにそのキーのポーズを編集する。保存・破棄の流れは点と同じ）。「カメラも動かす」がオンなら、カメラを正面に置いて、軸が距離ならその距離へ、画角ならその画角へ合わせる
- プレビュー: カメラの距離 / 画角に応じて補正が動く。プレビューの箱に今の軸の値と「パース補正の強さ」のスライダー（キーを打てる。`.fctrack` には固定カーブ `perspective` として入る）
- 検証: 同じ値のキー、未ベイク / ベイク後に変更、対応するキーの無い `FC_…_Persp_K{n}`（既存の孤立の検査）

### 5.9 検証・リペア（検証タブ、R-31）

- 検出: 参照しているシェイプ / ボーンがモデルに無い、大小違いだけの不一致、未ベイク・ベイク後に変更、孤立した FC_*、空のレイヤー、名前の衝突、可動域の外の値、ミラー相手が無い、左右非対称の頂点、プロファイルの標準シェイプの不足
- 修復: 似た名前の候補を出して**一括改名**、消えた参照の削除、再ベイク
- 無い名前は黙って 0 として扱い（止めない）、検証で一覧に出す
- 重さの区分: **エラー** = 構造の問題（基準ボーンが無い・格子が不正・レイヤー 0 が Neutral でない・レイヤー名の重複 など）/ **警告** = 参照先が無い・大小違い・可動域の外・ベイク後に変更・孤立した FC_* など / **情報** = 未ベイク・空のレイヤー・標準シェイプの不足 など。一覧は `core/validate.py` の冒頭
- 「ベイク後に変更」は、焼いたときのポーズのハッシュ（`pose_hash`）との比較で判定する。左右非対称の頂点はデータだけでは決められないので、シェイプタブのミラー機能（F2-2）で調べる

- 2026-10-03 追加（レビュー C-4 / C-5）: 値そのものの検査 — 数でない値（NaN / 無限大）`non_finite_value`、ミラーの軸 `mirror_axis_invalid`、自動生成の設定 `autogen_invalid`、メタ情報 `meta_invalid`、格子の大きさの上限（1 辺 64）`grid_size_invalid`。JSON の読み取りは Python と C# で同じ厳しさ（NaN / Infinity / 桁あふれは拒否、入れ子は 256 まで、整数は 32 ビットに収める）
- 2026-10-03 追加（レビュー C-1）: 名前の衝突の警告 `fc_name_ambiguous` — キャラクター ID とレイヤー名の組み合わせが、シーンにある別のキャラクターの補正シェイプと同じ名前になるとき（例: `a` のレイヤー `b_Joy` と、`a_b` のレイヤー `Joy`）。レイヤー名かキャラクター ID を変える

### 5.10 出力（出力タブ）

- **Unity 向け**: 顔メッシュを含むモデルの FBX（FC_* 入り・`fcs_*` と作業用ノードは除く・ブレンドシェイプ法線の設定を固定）+ `.fcpose.json` の写し → `facial/<character>/export/unity/`。Toon の Unity 出力と同じ別プロセス方式
- **UE 版向け**: `.fcpose.json`（座標系はそのまま `meta` に書く）
- **Timeline 用**（§7.3）: ショットごとの感情・強さ・角度指定のカーブ `<Shot>__<Model>.fctrack.json`

## 6. Unity（ランタイム・プレビュー・簡単な調整）

パッケージ `unity/com.tdrive.facial`（T-Drive リポジトリ内。Toon のパッケージとは別、同じバージョン・同じタグで配布。D-Drive に依存しない）。
Unity のメニューは **Tools › T-Drive › …** に置く（メニューバーに「T-Drive」というタブは作らない。D-Drive の Tools › D-Drive と同じ並び。2026-10-03 決定）。部品の追加メニュー（Add Component › T-Drive）とアセット作成メニュー（Create › T-Drive）はそのまま。

### 6.1 取り込み

- `.fcpose.json` → `FacialCorrectionData`（ScriptableObject）。ランタイムが使うのは格子・レイヤーの名前・方針だけの軽いデータ。ソースのポーズはエディタ専用の欄に保持（格子の閲覧用）
- FBX: Blend Shape Normals の推奨設定（**Import**。Maya が計算した法線を使う）を検証で確認（違っていたら情報として知らせるだけで、自動では変えない）。FC_* が格子どおりにそろっているかを検証

### 6.2 ランタイム `FacialCorrectionRunner`

キャラクターの Prefab に付けるコンポーネント。処理の順（UE 版と同じ）:

1. 視点を決める: 手動の角度 > 指定した Transform > メインカメラ
2. 基準ボーンと視点から Yaw / Pitch（頭の傾き・ロールは無視 = 直立を仮定。UE 版と同じ）
3. 角度が大きく飛んだら「スナップ」（カット切り替え）
4. 感情の重み（コンポーネントの値 / Timeline / Animator パラメータ）。ミュートしたレイヤーは除く
5. 重みの計算: 軸ごとに `u = (角度 / 範囲 + 1) / 2` → まわり 4 点の双線形の重み × 端のフェード × レイヤーの重み（Neutral は常に 1、感情は重みを掛けて上乗せ）。未ベイクの点・重み 0 は飛ばす。角度の変化が小さく感情も同じなら前回の結果を使う
6. 全体に掛ける: `(1 − expressionDampen × 表情の強さ)` × 距離フェード × 全体の強さ × Timeline / コンポーネントの強さ
7. 可動域で切る → スムージング（重みごと。スナップ時は即時）→ **LateUpdate で**ブレンドシェイプへ書く（Unity は 0〜100）。前のフレームに書いて今回は 0 のものは 0 に戻す
8. マテリアルへ出力（§6.4）

- シェイプ名 → 番号は最初に引いておく。無い名前は飛ばす。見えていないときは計算しない設定、LOD による打ち切りあり
- 書くのは FC_* だけ。アニメーション（Animator・D-Drive の `AnimData.BlendShapes`）が書く通常のシェイプとは衝突しない
- 無効化・プールへ返すとき、書いた FC_* を 0 に戻す

### 6.3 プレビューと「簡単なパラメータ調整」

| 機能 | 内容 |
|---|---|
| プレビュー | 再生していなくても、Scene ビューのカメラで補正を掛けて確認（オン / オフ、A/B、ターンテーブル） |
| 格子の閲覧 | 格子の状態（キー / 自動生成 / ベイクの有無）を表示。点をクリックで Scene ビューがその角度へ。今のカメラ角度も表示 |
| 検証 | FC_* の過不足、基準ボーン、取り込み設定、参照名の有無 |
| デバッグ表示 | 角度・重み・スナップの HUD と、頭の前方向・格子の 3D 表示（オン / オフ） |
| **調整できる値** | 全体の強さ、追従の速さ、スナップの角度、距離フェードの開始 / 終了、表情での弱め具合、端のフェード、シャープさ（R-32）、コマ打ちの fps（R-33）、感情の重み、レイヤーのミュート、視点の指定 |

- 調整値は「取り込んだデータ」とは別に保存する（`FacialCorrectionOverrides`。**取り込み直しても消えない**）。Maya へ戻したいときは JSON（`policy` / `quality` の部分）で書き出して Maya で読む
- 格子・ポーズ・シェイプは Unity では変えられない（Maya で直して出し直す）

### 6.4 マテリアル連携（R-14、任意）

`material.mode = "propertyBlock"` のとき、対象の Renderer に MaterialPropertyBlock で次を書く（グローバルには書かない = 複数キャラクターで衝突しない）:

| プロパティ | 値 |
|---|---|
| `_FC_Angles` | (yaw, pitch を −1〜1 に正規化, 全体の強さ, 0) |
| `_FC_Emotion0` … | 感情レイヤーの重み（4 つずつ Vector4） |

T-Drive の Toon シェーダー側で使う場合は、`_Toon` 接頭辞の受け口を別チケットで足す（角度に応じた線幅・顔影の補正など。[03](03_shader_spec.md) のパラメータ契約に従う）。

## 7. TimeLine 連携（D-Drive）

D-Drive の TimeLine は Unity Timeline の薄いラッパー（`CutsceneData` が `.playable` を指し、`CutsceneManager` が手動で時間を進めて評価する）。Unity 標準の仕組みでトラックが見つかるので、**T-Drive のトラックは D-Drive を変えずに載る**。

### 7.1 トラック `FacialCorrectionTrack`

- バインド先: キャラクターの `Animator`（D-Drive のバインドは Animator か Transform を渡すため）。その子から `FacialCorrectionRunner` を探す
- クリップ `FacialCorrectionClip` の値（クリップ同士はブレンドできる）:

| 値 | 用途 |
|---|---|
| 強さ | このカットだけ補正を弱める / 切る |
| 感情の重み（レイヤーごと） | 表情に合わせた補正の切り替え（Joy 0 → 1 など） |
| 角度の固定 | 決め構図で Yaw / Pitch を手で指定（R-29。カメラが動いても補正を動かさない） |
| 視点の指定 | 補正の基準にするカメラ（カットのカメラ以外を使うとき） |
| カット補正（R-36） | `poses/*.fcpose.json` のポーズをこのクリップの間だけ加算（ショット単位の手直し。元データを書き換えない） |
| コマ打ち（R-33） | このカットだけ更新の fps を変える |

- 連続的に値を当てるトラックなので、シーク・スキップ・一時停止・ネットワーク同期（D-Drive はシーク位置を同期する）にそのまま追従する
- Timeline ウィンドウでのスクラブ（再生していない状態）でも見える。プレビューを抜けたら値を元に戻す

### 7.2 D-Drive での使い方（変更なしの範囲）

1. D-Drive のモデル Prefab（`ModelData.Prefab`）に `FacialCorrectionRunner` を付け、`FacialCorrectionData` を指定する
2. `CutsceneData` の `.playable` に `FacialCorrectionTrack` を足し、`Bindings` でそのキャラクターの Animator と同じ相手に結ぶ
3. `Cutscene.Play(...)` で再生すると補正も一緒に動く

「キャラクターのアニメーショントラックと同じモデルに自動で結ぶ」などは D-Drive 側の追加が要る（[16](16_ddrive_changes_for_facial.md)）。それまでは T-Drive のブリッジ（`Bridges/DDrive`、D-Drive があるときだけコンパイル）が、同じ役名のアニメーショントラックのバインド先を引いて補う。

### 7.3 Maya で付けた演出を Timeline へ（Timeline 用の出力）

Maya のショット（D-Drive のカットシーン用 FBX を出すシーン）で、プレビュー用ノードの「強さ・感情の重み・角度の固定」にキーを打っておくと、
`<Shot>__<ModelIdentifier>.fctrack.json`（D-Drive のカットシーン FBX と同じ名前の付け方）として出力できる。
Unity 側のブリッジが、D-Drive の作った `.playable` に `FacialCorrectionTrack` を足す / 更新する（自動で作ったトラックだけを名前で照合して更新し、デザイナーが足したものは残す = D-Drive の再取り込みと同じ流儀）。

## 9. 計算の一致（UE 版・Maya・Unity）

- 重みの計算（角度 → まわり 4 点の重み、端のフェード、感情、表情での弱め、距離フェード、スムージング）と角度の計算、自動生成は、
  **Python（Maya）と C#（Unity）に 1 つずつ**実装し、同じテストデータ（JSON）で結果を比べる。許容誤差は重み 1e-4
- テストデータは UE 版の自動テスト（`FacialCoreTests.cpp` の 11 件）を写して起こし、T-Drive リポジトリに置く。UE 版が出力機能を持ったら突き合わせる
- UE 版の文書とコードが食い違う所は**コードを正とする**（感情レイヤー: Neutral は常に全量、感情は差分を上乗せ）
- Maya のカメラ連動プレビュー（ノードと expression）も、同じテストデータの入力で Python の計算と一致することを確かめる
- 座標系: 計算は UE 準拠の正準空間（cm / Z-up / 左手 / 前 +X）で定義し、各環境の入口で変換する。変換込みのケースをテストデータに入れる

## 10. 対象外

- **リギングツール（FacialRig）**: ガイド → ビルド、コントローラ層、誇張層・カット補正層のリグ側、RigCore、ピッカー、ポーズライブラリ（UE 版リポジトリの `FacialRig_リギングツール仕様書_v1.md`）。今回は含めない（2026-10-03 決定）。R-20 も同じ
- Unity でのポーズ編集・ベイク（UE 版移植計画の Unity 段階 2）
- Blender・VRChat・Unity 5 への移植、Maya 2024 / 2025 対応（T-Drive は Maya 2026）
- 表情そのものの制御（表情プリセットの切り替え・まばたき・視線）。リップシンクは対応表まで（音声解析は外部）
- MetaHuman、テクスチャ / VAT へのベイク
