# 04. 技術の優先順位

検討中の調整内容（「アニメ的な嘘」70 項目 + インナーライン + カメラ依存変形）と、一般的なセルルック技術を
**技術単位 (T-xx)** にまとめ、優先度を付けた。チケットは [tasks.md](tasks.md) でこの順に発行する。

## 1. 評価軸

| 軸 | 説明 |
|---|---|
| 効果 | セルルックとしての見た目への寄与（5=これが無いとセルルックに見えない） |
| コスト | Maya + Unity の実装コスト合計（1=半日〜1 日 / 5=数週間） |
| 持ち場 | **M**=Maya でアートデータを作る / **S**=シェーダー（Maya プレビュー + Unity 同式） / **U**=Unity ランタイム・レンダラー / **A**=モデル・リグ・アニメ運用 |
| D-Drive | ○=MaterialData（Common/Specific/RQ）で完結 / △=メッシュデータ（頂点カラー・法線・UV）や MS2026 側設定が必要 / ×=Renderer Feature 等、マテリアル外の仕組みが必要 |

**優先度の決め方**: `効果 ÷ コスト` を基本に、(1) セルルックの成立に必須なもの、(2) 後の技術の土台になるもの を繰り上げ、
(3) PBR 系、(4) マテリアル外の仕組み（D-Drive 適合×）が必要なもの を繰り下げる。

**大きな順序は「ルック → アニメーション」**（ユーザー指定）。アニメーション系はルックの P2 まで終えてから着手する。

| 優先度 | トラック | 意味 |
|---|---|---|
| **P0** | ルック | MVP。これが揃うと「UnityChan がセルルックで見え、部位別に調整・A/B できる」 |
| **P1** | ルック | 顔・髪のクオリティを決める。P0 完了後すぐ |
| **P2** | ルック | カメラ依存・スクリーンスペース・高コスト。Unity 側の設計と合わせて着手 |
| **A1** | アニメーション | 低コストで「生きている」感が大きく上がるもの |
| **A2** | アニメーション | リグ・ボーンスケール・カメラ連動が必要なもの |
| **X** | 対象外 | PBR 系・ポストプロセス。ツールでは扱わない |

## 2. 重要な設計判断

### D-1: マスクは「頂点カラー」を主、テクスチャを補助にする

ShadowMask・線幅などキャラクター固有のアートデータは **頂点カラー (RGBA)** に持たせる。

| 観点 | 頂点カラー | テクスチャ (`_ToonMaskMap`) |
|---|---|---|
| Maya での作成 | 標準の Paint Vertex Color Tool でモデル上に直接塗れる。**塗った瞬間プレビューに反映** | 3D ペイント / 外部ツール → 再読込 |
| Unity への移送 | FBX に乗る（メッシュ）。D-Drive の TextureData・インポート規約に触れない | TextureData 追加 + **リニア扱いのインポート規約が必要**（D-Drive の `_M` は PBR Mask 規約） |
| 解像度 | 頂点密度依存（顔・髪は十分、細部は不足） | 高い |

→ 頂点カラーで大半を賄い、頂点密度が足りない細部（鼻線・目周りの細い影）だけ `_ToonMaskMap` で上書きする。
頂点カラーのチャンネル割当は [03_shader_spec.md](03_shader_spec.md) §4。

### D-2: 描画順の嘘（眉を髪の上に）はまず「ビュー空間デプスオフセット」で実装する

ステンシル方式は Unity でしか再現できず Maya でプレビューできない。
カメラ方向へ頂点を寄せる **デプスオフセット（`_ToonDepthOffset`）** は Maya/Unity 同式で再現でき、Specific 1 個で完結する（D-Drive ○）。
破綻（顔の輪郭から眉がはみ出す等）が問題になった段階でステンシル方式（T-24）に上げる。

### D-3: アウトラインは「背面法線押し出し」を P0、スクリーンスペースは P2

背面押し出しはシェーダーのパス追加だけで済み（URP の `SRPDefaultUnlit` パス）、MaterialData で完結する。
スクリーンスペース（Depth/Normal/MaterialID のエッジ検出）は Renderer Feature が必要で D-Drive の管理外になるため後回し。

### D-5: Maya プレビューは Unity とシェーダーコードを共有する（dx11Shader）

描画パリティ（ギャップ最小化）のため、式は `ToonCore.hlsl` 1 本にして Unity・Maya の両方から include する。詳細は [09_render_parity.md](09_render_parity.md)。

### D-4: ライトはキャラクター専用の方向を持つ

影の境界の「パカパカ」防止・顔影の作画コントロール・Maya との見た目一致のため、
シーンのメインライトとは別に **キャラクターライト方向** を持つ（Maya=プレビューライト、Unity=`Mats.SetGlobalParam` で配るグローバル値 + 平滑化）。
