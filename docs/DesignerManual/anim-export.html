出力タブ

最終更新日: 2026-10-23

Unity（MS2026 / D-Drive）に渡すファイルを書き出します。モデルと、動き 1 つごとのファイルに分けて出します（D-Drive の決まり: モデルとアニメーションは別のファイル）。

ファイル中身
SK_<ModelId>.fbxメッシュ + スキン + スケルトン（骨）。アニメーションは入りません。バインドポーズ（基本の姿勢）で書きます。コントローラが動いたままのシーンでも、コントローラをゼロに戻してから書きます（戻せない骨があるときは出力のログに⚠が出ます）
A_<ModelId>_<動作>.fbx（クリップごとに 1 つ）骨だけ（メッシュなし）。クリップの範囲を 1 フレームごとに焼き込み（ベイク）、先頭が 0 フレーム。コントローラやコンストレイントは入りません。1 ファイルに 1 つの動き
humanoid.json / animset.jsonモデルと同じフォルダに書きます。Unity 側で人型の設定（Avatar）やアニメーションの設定を作るときの元データ
Model@Anim.fbx のような「@ で分ける」書き方は使いません（D-Drive の規則）。D-Drive は、アニメーションのファイルの最初の動きを、ファイル名で取り込みます。

出せないとき

出力ボタンが灰色で、赤い文字で理由が出ているときは、次のどれかです。

  • 合成中です — ブレンドタブ・ショットタブで「合成を外す」を押してください（合成の動きが FBX に焼かれてしまうので、合成中は出力できません）
  • 出力先の問題 — D-Drive のパスが main ブランチのとき（ブランチを切ってから）、MS2026 / D-Drive のパスが未設定のとき
  • 命名の❌があります（フレームレートが 30 fps でない、クリップ名に @ がある、スケルトンのルートが見つからない、など）。命名タブで直してから、「命名を確認」を押してください。命名の❌は、タブを開いただけでは調べません（「命名を確認」か出力ボタンを押したときに調べ、❌ があればそこで止まって理由が出ます）

出し方

  1. 出力先を選ぶ — 既定は、プロジェクトの build/unity/<ModelId>/（アニメは中の anim/）。MS2026 / D-Drive の SourceAssets は、「MS2026 のパス…」「D-Drive のパス…」ボタンで Unity プロジェクトのフォルダ（Assets の 1 つ上）を選ぶと使えます（選んでいないと灰色で、理由が出ます）。「フォルダを開く」で確認できます。4 つ目の「animset の指定先」は、animset の export.modelDir / export.animDir に書いたフォルダです。MS2026 へ書くときは毎回確認が出ます（MS2026 は本来読み取りのみのリポジトリです。既定は「いいえ」）。D-Drive のパスが main / master ブランチのときは出力を止めます（ブランチを切ってから出力してください）
  2. モデルを出力 — 出力するメッシュは animset に入っています。空のときは、スケルトンにスキンされたメッシュを自動で選びます。「スキンされたメッシュを animset に設定」で入れることもできます（そのあと上の「保存」）
  3. アニメーション — 出したいクリップにチェックを入れて「チェックしたクリップを出力」
  • 書き出しは別のプロセスで行うので、Maya はそのまま操作できます。開いているシーンは変更されません。進み具合は画面の中の進捗バーと、下のログに出ます（出力したファイルの名前・サイズ・警告）
  • 出力中は進捗バーの横に「中止」が出ます。押すと書き出しを止めます（書き終えたファイルは残ります）。ウィンドウを閉じても止まります
  • 同じ名前のファイルは上書きされます。ただし FBX はいったん別の名前で書いてから置き換えるので、書き出しの途中で失敗・中止しても、Unity プロジェクトの以前の正しい FBX は壊れません
  • FBX は単位 cm・バイナリ・FBX 2020 形式で書きます
  • モデルを出力すると、ログに「D-Drive に取り込むと ModelData の識別子は SK<ModelId> になる」という注意が出ます。D-Drive は SK_MisotenChara.fbx から SKMisotenChara という識別子を作り、カットシーンの MisotenChara と結び付かないので、取り込んだあとに ModelData の識別子を MisotenChara に直してください（D-Drive 側の直しを相談中。humanoid.json / animset.json の写しは、D-Drive が「対象外の拡張子」のログを出しますが、害はありません）
  • 参照（リファレンス）で読み込んだリグでも出力できます（書き出し用の一時シーンで参照を取り込んでから、ネームスペースを外します）

変更のあるクリップだけ

「変更のあるクリップだけ」にチェックが入っていると（既定）、前回の出力からクリップの範囲内のアニメーションや属性が変わっていないクリップは飛ばします（ログに「変更なしのため飛ばしました」と出ます）。出力先のファイルを消したときや、出力先を変えたときは、全部が対象になります。全部を出し直したいときはチェックを外してください。記録は anim/<ModelId>/.export-state.json に残ります（Git には入れません）。

変更を調べるのは、クリップの範囲内の各フレームの全ジョイントの姿勢（評価した結果）と、クリップの属性です。キーの接線・範囲外のキー・コンストレイントやリグの変更・アニメーションレイヤーの重みやミュートの変更も拾います（調べるのに少し時間がかかります）。ツールの出力のしかたを変えたときは、全部が対象になります。迷ったら、チェックを外して全部出してください。

ルートモーション

クリップの「ルートモーション」が none（既定）のとき、腰（Hips。humanoid.json の Hips のジョイント。無ければスケルトンのルート）の前後・左右の移動（X と Z）は、クリップの最初の位置に固定されます。その場で動く待機や走りのアニメーションに使います。bake のときは、動きをそのまま出します。上下（Y）は固定しません。

ショットの出力（D-Drive のカットシーン用）

ショットタブで開いているショットを書き出します。D-Drive のカットシーンの決まり（ファイル名・書き出しオプション）にそのまま合わせています。

ファイル中身
<Shot>.fbxカメラ（複数のカメラの区間を1 台のカメラ「Ubercam」に焼いたもの）・小道具（PRP_）。キャラクターは入りません。イベント（EVT_）は、「イベント（EVT_）も <Shot>.fbx に入れる」にチェックを入れたときだけ入ります（既定はオフ。D-Drive は EVT_ を読めず、小物のトラックとして取り込んで警告が出るため。D-Drive に Signal マーカーを置く対応が入るまで、マーカーは手で置きます）
<Shot>__<ModelId>.fbxキャラクター 1 体ぶんの骨だけ（メッシュなし）。ショットの範囲を 1 フレームごとに焼き込み。クリップ列のクロスフェードを含んだ動きになります。同じキャラクターが 2 体目なら _2
<Shot>__<ModelId>.fctrack顔の演出（任意）。キャラクターで「顔の .fctrack」を「あり」にしていて、Facial タブにデータが開いているときだけ
<Shot>.shot.jsonショットの内容の写し（Unity は読みません。この道具で作り直すとき用）
  • 出力先: 既定は build/cutscene/<カテゴリ>/。MS2026 / D-Drive を選ぶと …/SourceAssets/Cutscene/<カテゴリ>/ に書きます（カテゴリは shot.json の export.category。既定 Cutscene）
  • FBX の設定は、D-Drive の手順どおり: アニメーション ON、ベイク（開始〜終了 = ショットの全フレーム、1 フレームごと）、カメラはカメラの FBX だけ ON、ライト OFF、メディアの埋め込み OFF、入力のつながり OFF、キャラクターはスキン／変形モデル／ブレンドシェイプ OFF、単位は cm、上方向は Y。同じショットのすべてのファイルで、開始と終了のフレームが揃います
  • 同じ名前のファイルは上書きされます（D-Drive は、同じ名前で上書きすると、自動で作ったトラックだけを差し替えます）
  • FBX のジョイント名にはネームスペースが付きません（SK_<ModelId>.fbx と同じ名前）
  • カメラの切り替わりの瞬間は、補間せず前のカメラの値を次のフレームまで保ちます
  • ショットの出力ボタンが灰色のときは、赤い文字の理由を直してください（ショット名、フレームレートがシーンの時間単位と違う、キャラクターの animset のフレームレートがショットと違う、カメラの区間がシーンにない、キャラクターの animset がない、合成中、など）。ボタンを押す前に、理由が見えます
  • 同じ ModelId のキャラクターを 2 体置くときは、別のネームスペースにしてください（同じネームスペースは同じスケルトンを指すので、出力できません）。2 体目のファイルは _2 が付きます
Unity（D-Drive）に置いて CutsceneData が自動で作られることは、まだ人が確認していません（確認中）。置き先は D-Drive の確認用ブランチ tdrive-facial で試してください。

仮の決め

  • 出力先の既定は build/ です。MS2026 の Assets/_Project/DDrive/SourceAssets/ に直接出す機能はありますが、MS2026 は読み取りのみの決めなので毎回確認します（確認中）
  • Unity 側での Avatar や AnimatorController、AnimData の自動作成は、このツールではまだ行いません（humanoid.json / animset.json を元に、あとで作る予定です）
  • FBX のテイク名は Maya の既定（Take 001）です。D-Drive は最初の動きをファイル名で取り込むので、影響しません
  • Ubercam は、Maya の「Ubercam 作成」ではなく、この道具が各フレームのカメラの位置・向き・画角を 1 台のカメラに写して作ります（結果は同じ考え方です）。カメラの名前は Ubercam です
この画面の写真は実機で撮ったものを足します（準備中）。
